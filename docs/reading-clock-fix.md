# 0.25.1 阅读计时修复

计时条件保持不变：正文已排版并在前台可见，主窗口获得焦点，未手动暂停、未锁屏，且没有遮挡阅读的应用内弹窗。仍按书籍与自然日保存，日/周/月/年统计使用同一份本机阅读数据。

## 原因

- 旧展示将已保存的时间与前端独立推算时间相加；后台失焦停止后，前端可能尚未收到状态，数字继续增长。收到真实总量后数字回退。
- 页面重新渲染时使用旧快照，而即时标签使用推算值，两个展示口径不一致。
- 翻页排版结束的心跳受 3 秒节流影响，恢复累计可能延迟。
- 暂停、恢复或焦点变化时，如前一个请求尚未返回，强制更新会被直接丢弃。

## 修复

- 每秒读取后台确认并保存的时长，取消前端独立累加。刷新与即时标签调用同一个格式化函数。
- 正文排版完成后立即确认状态；请求在途时保留强制更新，返回后补发。
- 切换书籍后忽略旧书响应；重新打开书籍先恢复本书当天和累计时长，避免临时归零。
- 不在阅读页且计时已停止时，不继续轮询。

## 验证

`reading-display.test.cjs` 覆盖刷新回退、旧书响应、请求在途暂停及重新打开初始值。
`reading-runtime.test.cjs` 使用可控时钟与窗口事件，验证精确累计、双重心跳去重、失焦、暂停和锁屏。
`reading-clock-ui.spec.cjs` 使用隔离的 Electron 数据目录，控制窗口焦点以消除测试时其他应用抢焦点的干扰，对比 23 秒墙钟时间与真实落盘总量，连续刷新并检查显示单调性，再验证翻页、手动暂停、后台、锁屏、恢复和重新打开。设置 `YIXU_TEST_FORMAT=pdf` 同时覆盖 PDF。

此修复不会重写历史阅读总量；过去未保存的时间不能可靠推算补回。
