# 一序安卓与多端同步设计方案

日期：2026-09-30

实施状态：安卓第一版和桌面同步入口已实现，Supabase 项目与私有存储已部署，当前等待个人账号注册登录后的完整双端联调与安卓真机验收。已交付范围与未实现部分见 [第一版说明](mobile-v1.md)。

## 产品目标

手机随时打卡、写日记、拍照记事、保存学习网址；电脑继续管理七列表格、阅读与复盘。电脑关闭时手机仍可保存和同步。断网先保存在设备，联网后补传。首次范围为个人账号、手机与一台或多台电脑。

## 第一版页面

底部四个入口：今天、记录、计划、我的。

- 今天：今日安排、习惯及每周目标、一键打卡、专注入口、主动休息。打卡与计时习惯保持两套数据。完成后出现下一步提示，由本人确认。
- 记录：按日期切换日记、便笺、拍照/相册图片、稍后学习。支持安卓分享网址到一序；笔记正文直接显示图片。
- 计划：当天列表为默认视图；本周表格横向滚动。整体任务可设置每周次数、编辑、安排到某天；表格状态自动累计整体进度。
- 我的：回顾、同步状态、设备管理、通知权限、本机缓存、导出与备份。

手机记录时显示“已保存本机”，联网补传成功显示“已同步”；语雀另显示“已归档/待归档”。冲突需要处理时才显示提示，不干扰正常输入。

第一版包含文字、图片、打卡、习惯、专注、周计划、月历、日记便笺、稍后学习网址和基本回顾。完整 PDF 阅读器、视频浮窗、小游戏和复杂图表放到后续；手机视频通过系统浏览器打开，保留旁边笔记的快速入口。

## 技术选择

优先评估 Capacitor 安卓安装包 + Supabase 免费后端。Vercel 仅在需要网页入口时加入，不作为安卓客户端的必需依赖。免费额度、项目休眠、网络质量需要在正式接入前复核；先用手机移动网络和家中 Wi-Fi 做连接与上传验证，再确定区域与供应商。

现有界面可复用，但 Electron/Node 本地文件、锁、通知、浏览器窗口依赖需要替换。抽出共享业务规则和状态接口；桌面通过现有 IPC 适配，安卓通过本地数据库/系统插件适配，不将 Electron 程序直接装进手机。

两端本地保存，云端 PostgreSQL 保存结构化数据，私有对象存储保存附件。安卓本地数据库优先 SQLite；桌面先兼容现有数据文件并增加持久化变更队列，避免一次改写全部现有存储。

## 账号与设备

个人账号登录；首次桌面绑定时明确提示上传范围，保留原始数据备份。安卓登录同一账号后下载已有记录。支持退出、撤销某设备、重新配对。优先评估邮箱密码/验证码，短信登录留到后续，避免额外短信费用与配置。

每张表以 owner_id 隔离，开启并验证 RLS。客户端只使用公开项目配置及本人的短期会话；服务管理密钥不进入 APK、桌面包或 Git。语雀 Token/Cookie 保留在桌面，第一版不上传到同步服务。

## 数据及同步规则

各记录保存稳定 ID、所属账号、版本、创建/修改时间与删除标记。时间用于展示，服务端版本用于判断冲突，不依赖两台设备时钟一致。

- 打卡：保存带唯一操作 ID 的增减事件，联网重试按 ID 去重；撤销对应操作。双方加一次就是两次，不互相覆盖当天数字。
- 习惯：状态记录与专注会话独立；结束会话不自动视为完成。周次数与分钟目标使用实际事件/会话计算，最低版与休息单独统计。
- 周计划：整体任务和每日安排通过 taskId 相连，目标次数与表格进度统一计算。完成、撤销、移除、恢复都重算；同一操作不重复累计。各周数据隔离，延续只带剩余目标和来源。
- 日记、便笺、学习笔记：上传时带基准版本；冲突保留本机和云端两份正文，由用户合并。第一版不承诺自动合并任意富文本。
- 普通设置与标题：按记录版本更新，冲突提示保留当前输入；删除标记参与同步，防止旧设备把删除记录复活。
- 阅读进度：后续增加书籍内容指纹与版本；进度冲突可选继续位置，阅读时段合并时去除同设备重传及跨设备重叠计时。

客户端：本机事务保存记录与 outbox → 上传变更 → 服务端事务校验版本/操作 ID → 拉取游标之后的变更 → 本机应用并确认。重试不丢队列，失败使用退避；同步中正在编辑的草稿保持独立，不刷新输入区域。

服务器保存 change_log 与操作去重记录；拉取使用服务端递增游标及分页。完整首次同步与后续增量同步采用同一规则。通知重复触发不导致重复记数。

## 图片和书籍

图片在本机先保存，正文引用稳定附件 ID；对象上传成功后关联云端附件。图片显示缩略图，原图按需加载；附件使用私有存储和有期限的授权 URL，不把临时 URL 永久写入正文。

上传前限制文件类型和体积、压缩手机照片，按内容指纹去重，失败可重试。正文与附件分别显示同步状态，无法上传图片时文字仍保留。上传与下载使用存储接口，避免大文件穿过普通同步接口。

PDF 第一版默认只在本机，后续可选择同步某本书，先显示大小并确认。存储用量与缓存清理入口可见；移除本机缓存不删除云端原件。云端附件回收需要等待无正文引用并保留恢复期。

## 语雀归档

第一版维持桌面执行语雀图文同步。手机写入 → 云端同步 → 桌面下载 → 根据用户设置归档语雀。桌面离线时手机显示“设备已同步，语雀待归档”。同一记录版本只归档一次；云端语雀编辑冲突不强制覆盖。便笺仍遵循现有规则，仅在明确汇入日记后归档。

后续如果要求桌面关机也立即归档，再单独评估服务端或安卓授权，不能直接搬运当前桌面登录会话。

## 提醒与专注

安卓系统本地通知根据下载到本机的规则安排；不依赖手机网页定时器。通知操作先写入本机，再同步；计时使用开始时间与暂停区间恢复，应用切到后台不丢计时。

提醒权限、精确时间权限、重启后恢复、休息日取消、重复次数、延后提醒和厂商省电策略都需测试。后台同步采用系统允许的任务，回到前台立即补同步，不承诺后台每秒实时。

用户可选择手机、电脑或两端提醒。离线设备无法实时知道另一端已完成，同步后取消剩余提醒；允许离线情况下出现重复提示，操作去重保证不会因同一提醒重放重复记数。

## 备份与迁移

首轮导入前备份现有桌面数据、图片与书籍，迁移保留既有 ID 和语雀映射。提供本机导出，免费后端缺少自动备份时由桌面生成独立周期备份，并验证恢复。数据结构含 schemaVersion，客户端保留未知字段；破坏性升级要求兼容检查。

## 实施顺序与验收

1. 网络验证、账号与私有附件原型：在本人手机网络上验证登录、上传、下载与权限隔离。
2. 同步核心：两个隔离客户端完成离线新增、重试去重、删除传播、冲突保留、首次迁移和恢复。
3. 安卓四个入口与快速记录：适配单手使用、软键盘、相册、拍照和分享网址。
4. 桌面接入：原有 CLI 和界面操作都进入变更队列，不改变已有文件访问与草稿保存体验。
5. 提醒、专注、语雀归档与真机验收：断网、锁屏、重启、后台、电脑关机、两端同时修改、重复通知点击均验证。
